The upstream fast-forward is written down and checked instead of remembered ([#815](https://github.com/ThinkFlowLab/FlyBot/issues/815)). `docs/release-runbook.md` records the one-window-per-version sequence — the release commit as the tag target, the dry-run's five gates, `PUT` to disable the ruleset, a `force: false` fast-forward, the restore in a `finally` and the read-back that proves it, then upstream's own release with the same four assets — with every read and write as a `node` snippet, because the box that runs it has no `curl` and no `jq`. `node .github/scripts/upstream-sync.mjs --check` answers the two questions the window needs, read-only: both `main` SHAs with `ahead_by`/`behind_by`, and the ruleset's enforcement with its bypass list; it exits 0 only when the two mains are the same commit and the ruleset is `active` with no bypass actor, and it exits nonzero naming the condition that failed. `--commits` names the commits the fast-forward would carry.
